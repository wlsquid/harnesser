# Harnesser rule files

Rules live as separate files in the chosen directory:
- Project: `./.claude/rules/`
- Specific paths: `./.claude/rules/` with a `paths:` frontmatter list
- Global: `~/.claude/rules/`

## Adding
1. Ask scope with AskUserQuestion if not already chosen (project / specific paths / global / don't save).
2. Filename: `harnesser-<kebab-slug>.md`. Create the directory if missing.
3. Check existing `harnesser-*.md` files for a duplicate or overlapping rule; update that one instead of adding.
4. Write this template (omit `paths:` unless scope is paths):

```markdown
---
generated-by: harnesser
harnesser-version: 0.1.0
created: <YYYY-MM-DD>
scope: project | global | paths
paths:
  - "src/**/*.cs"
---
<!-- Generated by Harnesser. Edit freely; keep the frontmatter so Harnesser can find it. -->
# <Short title>
- Never <rule>.
Source: user instruction, "<short quote>"
```

## Updating
Edit the file in place and add `updated: <YYYY-MM-DD>` to the frontmatter. For rules not generated by Harnesser, confirm with the user first.

## Deleting
Confirm with the user, then remove the file.

## Manual use
`/harnesser:add-rule <text>` — treat the text as the rule and follow "Adding".
